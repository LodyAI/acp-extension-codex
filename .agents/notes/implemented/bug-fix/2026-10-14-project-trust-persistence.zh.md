# 持久化 Codex 执行目录信任

Status: implemented
Translation: current

[English](2026-10-14-project-trust-persistence.md)

## 摘要

适配器原先只在原生线程操作中临时传入项目可信配置，没有将外部管理的 worktree
保存到 Codex 用户配置中。因此，在这些操作之前发现目录配置时，项目设置可能被跳过。
现在会话准备流程先通过原生配置 RPC 持久化规范化后的执行目录，再发现技能和 MCP，
并保留用户显式拒绝信任的设置。此策略先留在 Codex 适配器内部，其他 provider 有类似
需求时再考虑共享信任契约。

## 决策与范围

ACP 打开会话请求触发现有的适配器目录信任策略。适配器负责持久化，原生进程提供实际
配置路径和版本，因此账号独立配置目录不会误写到假定的全局路径。仅合并
`projects[canonicalCwd].trust_level`，保留其他配置。附加目录继续只在会话内处理；
逻辑项目归属仍独立于信任，参见[原生项目身份](../simplification/2026-09-20-native-project-identity.md)。
不增加 Core 能力，不根据宿主路径前缀猜测信任，也不授予整个 repos 目录信任。

新建、加载、恢复和 fork 共用会话配置准备。请求目录或规范目录显式配置为 `untrusted`
时，磁盘配置与会话覆盖均保留该决定。原生配置版本校验防止覆盖并发修改：发生冲突后
重新读取，最多尝试三次；其他错误直接终止会话打开。没有跨越准备阶段的后台写入或
信任缓存；连接断开时原生请求失败。已经完成的写入不会因后续步骤失败或 worktree
删除而撤回。传输失败可能发生在磁盘写入成功之后，下次打开时会重新读取再决定是否写入。

仅使用临时覆盖不能使信任持久化。直接编辑 TOML 会重复实现原生配置修改与并发行为。
根据产品选择暂不增加通用 Core 接口，待其他 provider 的需求明确后再定义共同语义。

## 验证与限制

测试使用真实 Codex 0.160.1 app-server、临时配置目录和合成项目，验证四条会话路径在
执行线程操作前能加载项目设置、重复操作不改配置、显式拒绝得到保留、并发其他修改及
并发拒绝不被覆盖，以及写入失败时不会打开会话。原生配置请求是真实调用；线程创建、
历史和模型目录使用测试替身，新增测试无需模型回合。现有套件覆盖会话元数据与项目归属。

ACP 会话请求之前适配器尚不知道 cwd。本改动不会撤回进程初始化时已经发出的警告，
不会改变沙箱或工具审批，也不提供信任撤销或清理。此次 macOS 本地验证未覆盖 Windows 运行时。

最终定向验证九个套件共 268 项通过，包含全部九项原生信任测试；TypeScript 检查、
适配器构建和 `git diff --check` 均通过。全量套件首次有 1,668 项通过、两项失败：
其中线协议测试替身的配置响应已补齐并通过定向复测；另一项 session-index 符号链接
清理失败已在未修改的适配器基线归档中复现。根仓库文档检查仍受未初始化子模块引起的
断链及其他基线文档问题影响。本次不包含发布或父仓库 gitlink 更新。
